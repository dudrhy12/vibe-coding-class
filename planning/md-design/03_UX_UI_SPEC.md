# UX / UI Spec

> 본 문서는 `planning/md-design/01_PRODUCT_BRIEF.md`, `planning/md-design/02_REQUIREMENTS_SPEC.md`를 기반으로 작성되었다.

## 1. Design Reference

Follow: `docs/DESIGN.md`

### 이 서비스의 적용 방식

DESIGN.md의 BMW M 시스템을 뼈대로 쓰되, 타겟(취업 준비생·MZ세대)에 맞게 톤을 조정한다.

| DESIGN.md 원칙 | 이 서비스의 해석 |
|---|---|
| 순흑(#000) 캔버스 | 배경 #0d0f0f — 차갑지 않은 따뜻한 다크 |
| UPPERCASE 헤드라인 | 한국어 헤드라인은 대소문자 대신 **짧고 단호한 어투**로 대체 |
| 0px 보더 라디우스 (기본) | 카드·버튼은 4px, 태그 칩·배지는 999px — 딱딱함 없이 |
| M 트라이컬러 강조 | 시스템 강조색: 소프트 코랄 `#FF6B6B` (알림·임박) + 민트 `#4ECDC4` (완료·성공) |
| 사진 풀블리드 밴드 | 랜딩 히어로에만 사용, 앱 내부는 카드 UI 중심 |
| 무장식 미니멀 | 유지 — 불필요한 배경색·그라디언트 없음 |

> **"MZ스럽고 귀엽고 정신없지 않게"** =
> 잘 정돈된 다크 UI + 공감 가는 카피 + 절제된 포인트 컬러 + 과하지 않은 빈 상태 일러스트

## 3. Landing Page

### Purpose

취준생이 "아, 이거 나 얘기네" 하는 순간을 만들고, 앱 화면으로 자연스럽게 이동시킨다.

### Required Sections

1. **Hero** — 헤드라인 + 서브헤드라인 + CTA 버튼 + 배경 이미지(데스크 위 노트북·서류 감성 사진)
2. **Problem** — 공감 카드 3장: "구글 드라이브에 묻혀버린 자격증 사본", "어느 이력서가 최신인지 모르겠음", "마감 당일에야 기억나는 서류 제출"
3. **Core Features** — 5개 기능을 아이콘 + 짧은 설명으로 소개
4. **CTA Band** — 버튼 1개 중앙 배치, 군더더기 없이

### Key Copy

| 위치 | 텍스트 |
|---|---|
| Headline | 취준 자료, 이제 한 곳에서 |
| Subheadline | 자격증부터 채용 공고 마감일까지 — 흩어진 것들을 모아드릴게요 |
| CTA Button | 지금 시작하기 |
| Problem Card 1 | "자격증 사본, 어디 저장했더라…" |
| Problem Card 2 | "이 이력서가 최신 버전 맞아?" |
| Problem Card 3 | "마감이 오늘이었어?!" |
| Features 소제목 | 취준에 필요한 건 다 여기 있어요 |
| CTA Band 헤드라인 | 지금 당장 써볼 수 있어요 |
| CTA Band 버튼 | 무료로 시작하기 |
| Footer 캐치 | 취준생 옆에 늘 있을게요 |

### Section Detail

#### Hero
- 배경: `#0d0f0f` 다크 + 텍스처 없음
- Headline: `font-size: 56px / font-weight: 700 / line-height: 1.1`
- Subheadline: `font-size: 18px / font-weight: 300 / color: #bbbbbb`
- CTA 버튼: 배경 `#ffffff`, 텍스트 `#0d0f0f`, `border-radius: 4px`, `padding: 14px 32px`
- 히어로 사진 영역: 우측에 데스크 감성 이미지 배치 (없으면 그라디언트 대신 빈 다크 공간 유지)

#### Problem
- 배경 밴드: `#131515` (캔버스보다 살짝 밝음)
- 카드 3장 가로 배치 — `border: 1px solid #2a2a2a`, `border-radius: 8px`, `padding: 24px`
- 카드 상단 아이콘: 코랄 `#FF6B6B` 계열 단색 SVG
- 카드 텍스트: 따옴표 안 짧은 공감 문장 — 따옴표 색 `#FF6B6B`

#### Core Features
- 5개 피처를 2-3열 그리드로 배치
- 각 피처: 아이콘(민트 `#4ECDC4`) + 피처명(700) + 한 줄 설명(300)

## 4. App Page

### Purpose

사용자가 실제 기능을 수행하는 화면. 한 화면에 너무 많은 정보를 쏟지 않고, 카테고리 전환으로 집중력을 분리한다.

### Layout

```
┌─────────────────────────────────────────────┐
│  AppHeader (로고 + 페이지 타이틀)             │
├──────────────┬──────────────────────────────┤
│              │  AlertBanner (만료·마감 임박)  │
│  SideNav     ├──────────────────────────────┤
│  ─────────   │  FilterTabs / SearchBar       │
│  자격증       ├──────────────────────────────┤
│  대외활동     │                              │
│  채용 공고   │  ItemList / ItemGrid          │
│  이력서       │  (카드 or 리스트 뷰)          │
│  포트폴리오   │                              │
│              │  EmptyState (항목 없을 때)    │
└──────────────┴──────────────────────────────┘
```

### Required Areas

| 영역 | 설명 |
|---|---|
| **AppHeader** | 로고 좌측 + 현재 카테고리 타이틀 중앙. 배경 `#0d0f0f`. 높이 56px. |
| **SideNav** | 5개 카테고리 아이콘 + 텍스트 레이블. 활성 항목은 좌측 2px 코랄 인디케이터. 너비 200px. |
| **AlertBanner** | 만료 30일 이내 자격증 또는 D-7 이내 마감 공고가 있을 때만 상단에 표시. 코랄 배경 `#FF6B6B` + 흰 텍스트. 없으면 숨김. |
| **ItemForm** | 각 카테고리의 "추가" 버튼 클릭 시 슬라이드다운 또는 모달로 등장. 필수값 레이블에 `*` 표시. |
| **FilterTabs / SearchBar** | 태그 칩 또는 드롭다운으로 필터, 텍스트 검색창. 공고 페이지는 진행 단계 탭 추가. |
| **ItemList** | 기본 리스트 뷰. 카드 간격 12px. 카드 배경 `#1a1a1a`, `border-radius: 8px`. |
| **EmptyState** | 항목 없을 때 섹션별 단독 일러스트 아이콘 + 공감 문장 + "추가하기" 버튼. |
| **StatusAction** | 채용 공고 카드 내 단계 변경 드롭다운. 단계별 색상 배지로 시각화. |

### Empty State Copy (섹션별)

| 섹션 | 아이콘 | 메시지 | 버튼 |
|---|---|---|---|
| 자격증 | 📄 | "아직 등록한 자격증이 없어요. 첫 번째 스펙을 추가해볼까요?" | 자격증 추가 |

| 포트폴리오 | 💼 | "완성한 프로젝트를 정리해두면 지원할 때 꺼내 쓰기 좋아요." | 프로젝트 추가 |

## 6. Interaction Rules

**항목 관리**
- 항목 생성 성공 → 입력창 초기화 + 폼 닫힘 + 목록 상단에 새 항목 추가 (애니메이션 없이 즉시)
- 필수값 누락 → 생성 버튼 비활성화 또는 클릭 시 해당 필드 테두리 코랄로 강조 + 안내 텍스트
- 항목 삭제 → "정말 삭제할까요?" confirm 없이 즉시 삭제 후 `undo` 토스트 3초 제공

**상태 변경**
- 단계 변경 드롭다운 선택 → 즉시 배지 색 변경, 별도 저장 버튼 없음 (자동 저장)
- 이전 단계로 되돌리기 → 동일한 드롭다운으로 이전 값 선택 가능

**필터**
- 태그 칩 클릭 → 즉시 목록 필터링, URL 쿼리 반영 (`?tag=마케팅`)
- 모든 필터 해제 시 전체 목록 복귀

**AI 이력서 점검**
- "AI 점검" 버튼 클릭 → 로딩 스피너 + "열심히 읽고 있어요…" 문구
- 결과 도착 → 원문 / 제안문 나란히 표시, 제안 채택 / 무시 버튼 제공
- 일일 호출 한도 도달 시 → "오늘은 여기까지! 내일 다시 사용할 수 있어요" 안내

**파일 업로드**
- 5MB 초과 → 업로드 전 클라이언트 사이드에서 차단 + "5MB 이하 파일만 올릴 수 있어요" 안내

## 7. Accessibility Rules

- 모든 `<input>`, `<select>`, `<textarea>`에는 연결된 `<label>`이 있어야 한다.
- 아이콘 전용 버튼(SideNav 아이콘, 삭제 아이콘)은 `aria-label` 필수.
- 색상만으로 상태를 구분하지 않는다 — 채용 단계 배지는 색 + 텍스트 레이블 병행.
- 주요 영역은 heading 구조를 가진다 (`h1` 페이지 타이틀, `h2` 섹션, `h3` 카드 제목).
- AlertBanner는 `role="alert"`로 선언하여 스크린 리더가 즉시 읽도록 한다.
- 모달·슬라이드다운 폼은 열릴 때 포커스를 첫 번째 입력 필드로 이동시킨다.
- 키보드만으로 전체 흐름(생성 → 조회 → 상태 변경 → 삭제)을 완료할 수 있어야 한다.
